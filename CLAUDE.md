# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

SereneFlow — a Compose Multiplatform (Android + iOS) routine/step timer with physics-based Canvas animations and synthesized audio/TTS guidance. Package root: `com.sereneflow.timer`. Kotlin 2.4, CMP 1.12, AGP 9 (uses the `com.android.kotlin.multiplatform.library` plugin, not the legacy `com.android.library`). Versions live in `gradle/libs.versions.toml`.

## Commands

Requires JDK 17/21 in `JAVA_HOME`.

```bash
./gradlew :androidApp:assembleDebug                 # Android APK -> androidApp/build/outputs/apk/debug/
./gradlew :composeApp:testAndroidHostTest           # Run commonTest unit tests on the JVM host
./gradlew :composeApp:testAndroidHostTest --tests "com.sereneflow.timer.TimerEngineTest"   # single class
./gradlew :composeApp:testAndroidHostTest --tests "com.sereneflow.timer.TimerEngineTest.<method>"  # single test
./gradlew :composeApp:compileKotlinIosSimulatorArm64  # Type-check/compile shared code for iOS

# iOS app (the Xcode pre-build script runs :composeApp:embedAndSignAppleFrameworkForXcode itself)
xcodebuild -project iosApp/iosApp.xcodeproj -scheme iosApp \
  -destination "generic/platform=iOS Simulator" build

swift tools/generate_icons.swift   # Regenerate all app icons (iOS asset catalog + Android mipmaps/adaptive + Play icon)

scripts/release                    # Start a release (see README "Releasing"); CI publishes release/v* pushes
scripts/ios_screenshots.sh build/raw-iphone && scripts/frame_screenshots.py build/raw-iphone store-listing/app-store/en-US/screenshots
```

Store credentials live outside the repo in `~/.config/sereneflow/` (`source store.env`) and in the
private GitHub repo's Actions secrets; never copy them into the repo. That includes the Apple team
ID: it lives only in `Secrets.xcconfig` at the repo root (git-ignored, from
`Secrets.xcconfig.example`), which `Version.xcconfig` includes with `#include?`, and in the
`DEVELOPMENT_TEAM` Actions secret, from which CI writes that file before archiving. Never put a
`DEVELOPMENT_TEAM` in `project.yml` or the pbxproj: it would override the xcconfig. Simulator
builds don't need the file; device builds and `scripts/ios_release.sh` do. Release work is documented in
README.md ("Releasing") and `store-listing/*/README.md`.

Run the Android app from Android Studio with the shared `androidApp` configuration (`.run/androidApp.run.xml`), which starts `SereneFlowActivity` directly. "Default Activity" starts the `.MainActivity` launcher alias, which is disabled once another theme's icon is chosen, and fails with "Activity class ... does not exist". To reset a device: `adb shell pm enable com.sereneflow.timer/com.sereneflow.timer.MainActivity`.

Don't pass `-sdk iphonesimulator` to xcodebuild: it forces the iOS SDK on every target, including the `SereneFlowWatch` watchOS app, which then fails ("AppIcon did not have any applicable content"). `-destination` alone picks each target's SDK, as Xcode and Android Studio do. A watch app built for iOS can't be embedded either: the simulator refuses to install it, so there is no workaround in project.yml.

Android Studio's iOS run configuration (Xcode Application, scheme `iosApp`) runs the pre-build script's `./gradlew` line itself through the Gradle Tooling API, then calls xcodebuild with `OVERRIDE_KOTLIN_BUILD_IDE_SUPPORTED=YES`, which the script checks to skip Gradle. Keep that `./gradlew` line free of CLI-only flags such as `--no-daemon`: the Tooling API rejects them and the run fails before xcodebuild starts. Its empty "Development team" field is fine; the team comes from `Secrets.xcconfig`.

Don't pass `CODE_SIGNING_ALLOWED=NO`: simulator builds are ad-hoc signed via `project.yml`, and an unsigned `SereneFlowWidget` extension never launches, so the Live Activity silently shows nothing.

`iosApp/iosApp.xcodeproj` is generated by XcodeGen from `iosApp/project.yml` — edit the YAML and regenerate (`xcodegen` in `iosApp/`) rather than hand-editing the pbxproj. Targets: `iosApp` (SwiftUI shell + `LiveActivityManager`) and `SereneFlowWidget` (Live Activity / Dynamic Island UI); `iosApp/Shared/TimerActivityAttributes.swift` is compiled into both. Kotlin iOS targets are `iosArm64` + `iosSimulatorArm64` only (static framework `ComposeApp`). App icons are generated by `tools/generate_icons.swift` — edit the script, not the PNG/XML outputs.

## Architecture

- **`composeApp/`** holds essentially all code (shared KMP module). `androidApp/` is a thin launcher (`SereneFlowActivity` sets `AndroidAppContext.appContext` then calls `App()`); `iosApp/` is a SwiftUI shell hosting `MainViewController()` from `iosMain`.
- **Navigation** is hand-rolled: `App.kt` keeps a back stack (`mutableStateListOf<AppScreen>`) and renders the top via `AnimatedContent`. Back (Android system back, iOS edge swipe) goes through `NavigationBackHandler` from `androidx.navigationevent:navigationevent-compose`; screens with unsaved state (editor, running timer) register their own enabled handler, which takes precedence and shows a confirm dialog. While a back gesture moves, `ui/PredictiveBack.kt` (`rememberPredictiveBackTransition`, a `SeekableTransitionState` driven by the handler's `NavigationEventState`) scrubs the screen transition toward the screen below; the editor's picker lists use it too. No navigation library, no ViewModels, no DI — repositories and the `AudioController` are created with `remember` in `App()` and passed down as parameters/callbacks.
- **Persistence**: `RoutineRepository` and `PreferencesRepository` (both in `repository/RoutineRepository.kt`) hold `MutableStateFlow`s loaded from JSON files (`routines.json`, `preferences.json`) via `storage/FileStorage` (`expect fun createFileStorage()`: Android `filesDir`, iOS Application Support). Every change is written back by a conflated collector on an injectable scope. The single seed routine appears only when no file exists, so deleting everything stays deleted. `AppPreferences` (in `model/Models.kt`) holds theme, the defaults that routines left at Default follow (`defaultVisualEffect`, `defaultSound`, `defaultVoice`), `reminderThresholds`, `keepScreenOn` (default on) and `backgroundMode` (off until the user accepts the prompt shown after their first routine save; `backgroundModeAsked` records the answer).
- **`session/TimerSession`** (process-wide `object`) owns the running routine's `TimerEngine` and the shared `AudioController`, so the timer survives the UI (activity recreation, app in background) and notification buttons can reach it. Voice control goes through `sereneflow://` links (`ExternalAction.parseUrl`; `TimerSession.control` for pause/resume/skip/end): Siri via the App Intents in `iosApp`, Google Assistant via App Actions in androidApp's `res/xml/shortcuts.xml` (built-in intents plus custom intents for the same phrases; the controls go to the window-less `TimerControlActivity`, so they don't bring the app forward). `App.kt` shows the timer screen whenever a session is active and leaving that screen stops the session. Every session's state changes go to `SessionPresenter.showOnCompanion`: on iOS the Apple Watch app (`WatchRegistry.bridge`, Swift `WatchSessionManager`, WatchConnectivity application context), whatever the setting; the watch treats a running snapshot as stale 30s after its step end, since a suspended or killed phone app stops refreshing it. With `AppPreferences.backgroundMode` on, they also go to `SessionPresenter.show`: Android → `TimerService` (foreground service, `specialUse`, partial wake lock while ticking) posting a chronometer notification with per-step `ProgressStyle` segments, Pause/Skip/End actions (`TimerActionReceiver`) and an Android 16 Live Update request; iOS → `LiveActivityRegistry.bridge` (Swift `LiveActivityManager`, since ActivityKit has no ObjC API) plus banners on step change while backgrounded, and `AudioController.setSessionActive` keeps the AVAudioEngine running (with the `audio` background mode) so the app stays alive. With it off nothing but the watch app shows the routine outside the app (and the phone app may be suspended in the background), but time stays correct. The watch's Smart Stack comes from the Live Activity, so it needs the setting.
- **`engine/TimerEngine`** is the timer state machine, driven by wall-clock time: each running step has an absolute end (`stepEndEpochMs`), a 200ms ticker re-reads an injectable clock, and `sync()` catches up through any steps that ended while the process was suspended. It owns a `StateFlow<TimerState>`, handles step transitions, per-step "% left" reminders (`reminderThresholds`, skipped for steps under 10s), 3-2-1 countdown chimes, session mute (`setMuted`/`toggleMute`), and plays a step's `CueSound` tone and/or speech per its `RoutineCues` (`Routine.resolve(preferences)`, done by `TimerSession.start`: a routine's null `visualEffect`/`sound` and `VoiceGuidance.DEFAULT` mean "use Settings"). Old files' `soundMode` is read as `LegacySoundMode` and split by `migrated()` on load. It takes an injectable `CoroutineScope` and `clock` — tests pass the `runTest` scope, `clock = { testScheduler.currentTime }` (or a manual `var now` to simulate suspension) and a `FakeAudioController`, and drive time with `advanceTimeBy`. `ActiveTimerScreen` constructs the engine per routine.
- **Audio** is an `expect fun createAudioController()`. Tones are synthesized in common code (`audio/ToneSynth`) and played by `AudioTrack` on Android and an `AVAudioEngine` player pool on iOS (session category `.playback`, so the ringer switch doesn't mute it; all AVFoundation calls hop to the main queue). Speech uses `TextToSpeech` / `AVSpeechSynthesizer`. Android needs `AndroidAppContext.appContext` set by `SereneFlowActivity` before `App()`. `-Xexpect-actual-classes` is enabled.
- **Platform UI** (`ui/platform/PlatformUi.kt`): `ConfirmDialog`, `ActionMenu`, `KeepScreenOn`, `PlatformIcons` are expect/actual — iOS presents native `UIAlertController` alerts/action sheets and uses iOS-style icons; Android uses Material `AlertDialog`/`DropdownMenu`. Use these instead of Material dialogs/menus in shared screens.
- **Visual timers** (`physics/*Canvas.kt`) take `progress: () -> Float` and read it, plus `rememberFrameTimeSeconds()`, inside the draw lambda so frames only redraw. All motion is a pure function of frame time (no per-frame mutation, no looping `infiniteRepeatable` phases) so it is smooth and frame-rate independent. `ActiveTimerScreen` passes `TimerState.stepProgressAt(nowEpochMs())`, exact from the wall-clock step end. Orbit uses the shared thick `drawProgressRing`; Orbit and Lotus keep the centre clear for the countdown digits. Adding an effect means a `VisualEffectType` entry, a Canvas composable, and a branch in `ActiveTimerScreen`. `VisualEffectType.RANDOM` is not an animation: `Routine.resolve` swaps it for one of `VisualEffectType.animations` at each start, so `RoutineCues.visualEffect` is never RANDOM.
- **Adaptive layout**: lay out from the space a screen has (`BoxWithConstraints`), never the device idiom or orientation: folding an iPhone Duo or resizing a window changes it mid-session. Forms use `ReadableWidth` (`ui/AdaptiveLayout.kt`) to stay at most 680dp wide; the routine list is an adaptive grid; `ActiveTimerScreen` scales its dial with the shorter side and moves the controls beside it when the window is wide. The canvases must size from their own `size` (fractions of the shorter side), not fixed pixels. iPhone Duo needs the iOS 27.1 SDK (Xcode 27.1; CI uses the `xcode-27` image).
- **Version and demo launches**: `Version.xcconfig` (repo root) is the one version of both apps: Gradle reads `MARKETING_VERSION` for `versionName`, and it is the Xcode project's base configuration. `DemoLaunch` opens a screen directly (debug builds only: iOS launch arguments in `MainViewController`, Android intent extras in `SereneFlowActivity`) for the screenshot scripts.
- **App icon per theme**: picking a theme in Settings also switches the launcher icon to that theme's (one per `AppThemeMode`); there is no separate icon setting, and the icon isn't switched at launch, as iOS would show its change alert unprompted. `tools/generate_icons.swift` makes them all (Zen Sage is the primary icon; the others are iOS alternate icons listed in `project.yml` and Android `<activity-alias>`es in androidApp's manifest (the default one is named `.MainActivity`, 1.0's launcher component, so old home-screen shortcuts survive), with previews in `composeApp/src/commonMain/composeResources`). `platform/AppIconSwitcher` reads the choice back from the platform instead of storing it; iOS goes through the Swift `AppIconManager` (`AppIconRegistry.bridge`) because the alternate-icon API is missing from the Kotlin/Native bindings. `AppIconAssetsTest` (androidHostTest) checks the names match on all three sides.
- **Launch screens**: the Android window/splash background (`androidApp` `Theme.SereneFlow`, `res/values*/colors.xml`) and the iOS launch screen (`LaunchBackground` colour) are Zen Sage's background, light and dark. Both are read by the system before any app code runs, so they can't follow the chosen theme; Android 12+'s splash icon is the tapped launcher alias's, so it follows the theme's icon.
- **Settings choices with many options** (default sound, voice) open a screen of their own (`ui/ChoiceScreens.kt`) from a row in Settings, rather than listing them inline.
- **Strings**: every user-visible, spoken or screen-reader string is a resource (English only so far; a language is added as files). Shared code: `composeApp/src/commonMain/composeResources/values/strings.xml` through `stringResource`/`pluralStringResource`, or the suspend `getString` outside the composition (the engine's `SpokenPhrases`, the seed routine); `text/ModelText.kt` and `text/DurationText.kt` word the model's enums, durations and counts, so the model holds no English. Android-only text (notification, shortcuts, Google Assistant query patterns): `composeApp/src/androidMain/res/values/strings.xml`. Swift: a `Localizable.xcstrings` per target (Shared/ strings in both the app's and the widget's), the app's `InfoPlist.xcstrings` and `en.lproj/AppShortcuts.strings` (Siri phrases; the catalog form needs iOS 17). Host tests can't load Compose resources, so engine and repository tests use English stand-ins (commonTest `TestText.kt`), which `StringResourcesTest` checks against strings.xml, along with every string being used.
- **Theming**: `AppThemeMode` enum → palettes in `theme/Color.kt` → `SereneFlowTheme` in `theme/Theme.kt` (Material 3).

## Notes

- Compose's iOS `PlistSanityCheck` aborts at launch unless `iosApp/iosApp/Info.plist` contains `CADisableMinimumFrameDurationOnPhone = true`; keep it.
- Edge-to-edge on both platforms (`ContentView.swift` ignores safe areas): screens must apply `WindowInsets.safeDrawing` themselves (Scaffold `contentWindowInsets` or `windowInsetsPadding`).
- `плохие примеры ЮИ/` ("bad UI examples") contains screenshots of UI to avoid — reference only, not app assets.
